# Malody 4.3.7 UIS 校准记录

本记录区分游戏本体证据、编辑器预览实现和仍需验证的推断。分析对象是用户提供的 `malody-4-3-7.apk`，SHA-256：`7b6f5650481f6b1e04ebe8eec93f18c2205521522f94da3f129cfb0c37044138`。不把 APK 或其内置资源提交到仓库。

## 已确认

- APK 的 `classes.dex` 和 `lib/arm64-v8a/libmalodycpp.so` 都含 `4.3.7` 版本字符串。游戏核心是已剥离大部分符号的 ARM64 C++/Cocos2d 库；Java 层主要负责 Android 容器，不能用 Java 反编译器直接看到 UIS 绘制实现。
- `assets/libskin.so` 是内置资源容器，不是 ELF 动态库。它含 300 个条目；条目头和长度允许提取明文 UIS 脚本。筛出的 55 份 UIS 文本片段均可由本编辑器的文本解析器读取，但原始文件名被哈希，部分 `@include` 无法直接还原，因此这不是完整的运行时验证。
- 游戏内置 UIS 文本使用 `@apply 3d`、`@angle 45`、`@unit`、`@if phone`、`type=5` 搭配 `rect`，以及 `opacity=85`。这些是 4.3.7 实际接受的写法；它们本身没有给出投影或绘制算法。
- Emiria 5.0 原型的 `UISFactory.Setup` 将 Mac 同时标记为 `mac` 和 `windows`。编辑器保留此兼容行为；APK 内置脚本没有提供足够信息验证 4.3.7 对 Mac 的同名条件细节。
- 两份明确写有 `@version 4.3.7` 的外部皮肤在 0 ms、PC 预览中能加载，没有组件不支持的日志。修改解析器后，两份截图曾与旧版逐字节一致；去掉可确定的调试标记后，分别有约 0.14% 和 0.17% 像素变化。

## 当前编辑器与原版的差距

| 项目 | 当前状态 | 证据边界 |
| --- | --- | --- |
| `@unit`、百分比、`w`、批量名称、定义和条件 | 已结合 Emiria 5.0 原型及真实 4.x 样本修正 | 632 份外部 `.mui` 文本与 55 份 APK 内置 UIS 片段通过文本解析；不等于每项渲染语义正确 |
| `@angle` 透视 | 编辑器保留 2024 年经验多项式，输出有回归测试 | APK 确认使用角度，但尚未从 C++ 库恢复相机与投影公式 |
| 自定义组件 `type=5` | 尚无对应渲染器 | APK 内置 UIS 多次使用 `type=5` 与 `rect`；当前 `toRenderer` 只处理 0–4 |
| note 的 hold `type=1`、`type=3` | 渲染分支未完整实现 | 当前 `NoteComponentRenderer` 的分支为空或缺失身体绘制；不能声称 hold 预览与游戏一致 |
| key／通用帧动画 | 现在跟随预览时间选帧 | 已消除系统时钟导致的固定帧不稳定；具体游戏触发时机尚未比对 |
| 得分、note、bar 的彩色辅助标记 | 已移除明显的调试绘制 | 不属于皮肤素材；去除后需用游戏画面作最终视觉验收 |

Emiria 历史 UIS 源码属于 5.0.0 原型，可提供格式线索，不能代替 4.3.7 的运行时实现。下一步应优先对 APK 中实际使用的组件类型做渲染覆盖，再把 C++ 中的坐标、透视和 note 行为与可运行客户端截图逐项对照。
